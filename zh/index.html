AI 起草,规则拍板。

我拿 AI 干活,但从不让它给自己的活打分。打分的必须是一个不会替它说好话的东西 —— 所以每一个结果,事后都还能再验一次。

看 Verdict 查一票货 ↓ 读 nonconstant 源码 →
  • nonconstant —— 给 AI 干的活装闸门;判不出来的时候它说判不出来,不说没问题
  • DevLoop —— 跑我的编程 agent;活算不算干完,由一套测试说了算
  • Verdict —— 读航空货运单证;放行还是拦下,由 57 条成文规则说了算
  • Terrarium —— 同一个种子,每次都重建出一模一样的世界

我怎么和 AI 一起做东西

按规则拍板而不是按模型拍板,不是一种偏好,是一张账单。得有东西在模型看见之前就定义好这次改动、拒绝它不该跑的命令,并且在不问它的前提下判断结果。这套东西我手工跑了几个月;五份文档加一套 hook 长成了 DevLoop,它是公开的、可以读的。它是第一版:其中一部分没能在一个更好的地基面前活下来,活下来的那部分正在那个地基上重建。

  1. 五份文档在模型看见之前就定义好这次改动

    五份作为事实来源的文档,加一条 17 阶段的 prompt 管线,在模型看见之前定义好每一次改动。

  2. hook 在命令跑之前就拒绝它,不是跑完之后

    自定义的执行前 hook 在危险命令和越出契约的编辑发生之前就把它们挡掉。

  3. 审查者能标出问题;它跑不了那条能证明问题的命令

    独立的子 agent 拿 diff 对着规格审。它们能标记,但不能写。

  4. 退出码决定完成,永远不是模型自己的报告

    pre-commit 跑类型检查、测试和构建;CI 再全部重跑一遍。绿是唯一被接受的证据。

  5. 每一种事故模式都映射到现在能抓住它的那道保险

    10 种记录在案的事故模式,每一种都映射到现在能抓住它的那道保险。其中一种是:模型为一条并不在它所声称的那个 hook 里的命令,报出了一个退出码。

我现在认为这份工作是什么

3 条关于「跟模型打交道」的前提、由它们推出的 5 条结论,以及它们解决不了的部分。下面每一个系统都在这些之下 —— 哪里系统和它们对不上,改的是系统。

很多好工作花在让这些系统产出更多、更快。这是另一半:刹车和仪表。

前提

这些前提是摊开写的,方便你不同意:

  1. A1模型在两次运行之间会忘掉一切。

    上一次学到的东西,除了有人写下来、又有人重新读过的那部分,没有一样活得下来。你依赖的每一条约定,要么是从零重新立一遍,要么根本就不在那儿。

  2. A2生产工作的成本塌了。检查它的成本没动。

    写出一版实现现在几分钟的事,判断这版实现对不对还是原来那么久。两边的价格差了几个数量级,而贵的那边是决定东西能不能发出去的那一边。

  3. A3错误会被后面的工作垒上去,而且垒得比它被发现要快。

    一个没被拦住的错误不会停在原地等人来查 —— 下一步会建在它上面,再下一步建在那之上。等它露头的时候,要拆的不是那一个错,是垒在它上面的整摞东西。

由此推出

推出什么,以及每一条逼你做什么:

  1. T1一条约束的强度,恰好等于裁判对被裁判之物的免疫程度。 由 A1

  2. T2工程价值已经从生产的那一侧,移到了检查的那一侧。 由 A2

  3. T3检查点之间的间距,必须小于错误被垒上去的速度。 由 A3

  4. T4意图只能存在三个地方:人的记忆,可以被绕过去说服;文件,可以被改;程序,两样都不是。 由 A1

  5. T5不改变任何可观测输出的失败会一直累积,直到成为灾难;它多久发生一次不在考虑之列。 由 A3

它解决不了的

它解决不了的 —— 是量出来的,不是预想的。这份清单早先有一版是动工之前写的,读起来更漂亮;下面这些是动工之后才冒出来的:

  • 检查能告诉你一个说法跟事实对不上。它没法告诉你这个说法背后的推理错了。说法本身依然是良构的,检查对它没有意见,而错误在检查看不见的地方。

    代价一个对根因的错误估计,在一块全绿的板子后面待了二十六个提交。打破僵局的是有人跑去把它量了一遍,而那不是一道关卡能被做成会去干的事。这是极限,不是缺口:诚实的回应是说清楚哪些结论靠的是判断,别再暗示机器把它们覆盖了。

◧这些你可以自己跑

什么都不用克隆,什么都不用信。下面三条,在你已经有的终端里就能跑:

  • curl -s https://hh0hh.com/rules.json | sha256sum 返回的摘要,就是上面 demo 里每一条判定旁边印着的那个。规则表是发出来的,不是描述出来的。
  • npm run release 规则摘要过期、分享卡片过期,或者输出里任何地方还留着未处理的占位符,它就拒绝构建。
  • node scripts/check-placeholders.mjs --release 上面那条里的最后一项,单独拎出来。我手工往 dist/ 里塞回一个违规,确认它退出 1 —— 一个只被证明过绿的检查不是检查。

诚实的局限

上面是合成数据的 demo;真实系统正在为一个客户开发中,不是一个公开产品。准确率是在那个客户的单据构成里、干净的数字版英文 PDF 上量的。不是扫描件,不是拍照件。规则编码的是我对公开法规的解读,由测试验证,不是由持牌报关行验证。没有任何关于生产流量的主张。

这个 demo 是怎么跑的

这个 demo 回放的是真实管线跑在合成货运单据上的预先录制输出 —— 同一套抽取 schema、同一个规则引擎、同一套判定逻辑。这里没有任何东西发起网络请求:没有 LLM API,没有追踪,没有数据离开你的浏览器。文档里的值是虚构的;规则 ID 和阈值为了展示做了简化。完整系统仍在为那个客户开发中;这次回放是今天真能跑的那部分,如实切出来的公开切片。
