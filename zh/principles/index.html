我现在认为这份工作是什么

3 条关于「跟模型打交道」的前提、由它们推出的 5 条结论,以及它们解决不了的部分。下面每一个系统都在这些之下 —— 哪里系统和它们对不上,改的是系统。

很多好工作花在让这些系统产出更多、更快。这是另一半:刹车和仪表。

前提

这些前提是摊开写的,方便你不同意:

  1. A1模型在两次运行之间会忘掉一切。

    上一次学到的东西,除了有人写下来、又有人重新读过的那部分,没有一样活得下来。你依赖的每一条约定,要么是从零重新立一遍,要么根本就不在那儿。

  2. A2生产工作的成本塌了。检查它的成本没动。

    写出一版实现现在几分钟的事,判断这版实现对不对还是原来那么久。两边的价格差了几个数量级,而贵的那边是决定东西能不能发出去的那一边。

  3. A3错误会被后面的工作垒上去,而且垒得比它被发现要快。

    一个没被拦住的错误不会停在原地等人来查 —— 下一步会建在它上面,再下一步建在那之上。等它露头的时候,要拆的不是那一个错,是垒在它上面的整摞东西。

由此推出

推出什么,以及每一条逼你做什么:

  1. T1一条约束的强度,恰好等于裁判对被裁判之物的免疫程度。 from A1

    模型给自己的活打分不是「弱检查」,那不是检查。所以判定权交给规则引擎、进程退出码,或者第二份独立实现。但退出码只在被裁判的那个东西够不到「开关」的时候才算数:我有一次只是在一行末尾加了个注释,就把一个守卫关掉了,而它继续报告零违规。

  2. T2工程价值已经从生产的那一侧,移到了检查的那一侧。 from A2

    有意思的活不再是把东西写出来。是把那套判断「东西到底做完没有」的装置搭起来 —— 然后故意弄坏它,亲眼看它变红。

  3. T3检查点之间的间距,必须小于错误被垒上去的速度。 from A3

    放在最后的关卡是损失发生之后的关卡,所以最便宜的那些检查要往下沉到工具调用这一层。这能拦住工具层看得见的写入。拦不住别的:有两条 shell 单行命令直接穿过了同一个 hook,文件是真的被写了。判断一条命令会不会写文件,是停机问题换了顶帽子,所以那条通道改成前后各拍一次快照来对 —— 那是抓住,不是拦住。

  4. T4意图只能存在三个地方:人的记忆,可以被绕过去说服;文件,可以被改;程序,两样都不是。 from A1

    这就是为什么「把规则写下来」一直失败。真正要紧的规则要配一条机械判据 —— 一条命令,它的输出就是这条规则 —— 而让它别再报警的唯一办法,是真的把事做了。

  5. T5不改变任何可观测输出的失败会一直累积,直到成为灾难;它多久发生一次不在考虑之列。 from A3

    沉默不是信号,所以没有任何东西给它踩刹车。一个清理例程把自己的输出接走了,又从不检查返回码;每一次失败都被吞掉,直到废弃工作目录数到 2,983 个、86 GB 磁盘把它顶住为止。现在失败必须吵 —— 尤其是在没人看着的时候。

被扣下的一条

还推出了一条,被扣着没用:

T6任何让「修复」随拖延而变贵的机制,最后保住的会是错误,不是修复。 候选 —— 扣下,未采纳

它要走一次修订才能转正,而会触发那次修订的阶段还没到。已经有三个各自独立的问题看着像是它的实例 —— 这是认真对待它的理由,不是提前采纳它的理由。

它解决不了的

它解决不了的 —— 是量出来的,不是预想的。这份清单早先有一版是动工之前写的,读起来更漂亮;下面这些是动工之后才冒出来的:

  • 检查能告诉你一个说法跟事实对不上。它没法告诉你这个说法背后的推理错了。说法本身依然是良构的,检查对它没有意见,而错误在检查看不见的地方。

    COST一个对根因的错误估计,在一块全绿的板子后面待了二十六个提交。打破僵局的是有人跑去把它量了一遍,而那不是一道关卡能被做成会去干的事。这是极限,不是缺口:诚实的回应是说清楚哪些结论靠的是判断,别再暗示机器把它们覆盖了。

  • 一个检查的覆盖范围,从它的结果上看不出来。凡是靠匹配文本找目标的检查,「什么都没匹配到」和「本来就没有可匹配的」会以同一个答案返回 —— 而它两种情况都报通过。

    COST八个检查一个一个审下来;六个有同一个缺陷,每一个都是手工复现的,不是靠推理认定的。改注释里的两个词,就能让一份超预算的文档悄悄合规。这比静默失败更糟,因为静默失败是沉默,而这个是一个绿勾。

  • 一个检查的开关,被它所检查的对象够得着。在一份受保护路径清单的某一行末尾加个注释,就让那条模式什么都匹配不上 —— 于是文件可以被改,而盯着这个文件的守卫报告零违规。一次编辑同时完成了越界和掩盖。

    COST仍然是开着的。修复需要同时做到两件事 —— 每条模式都必须被证明匹配到了某个真实存在的东西,而一条有意为空的模式必须自己大声说出来 —— 而这里修一半比不修更糟,因为它恢复了信心却没恢复覆盖。

  • 这套框架写下来的规则里,大部分没有任何人执行。二十九条规则;五条有机器检查。另外十一条本来可以有,而没有。十二条根本不可能有 ——「根因到底有没有被量过?」变不成一个退出码。

    COST把这个比例公开出来,就是代价。不写它,这东西读起来会像一套完整的约束系统,而它是五分之一套。这个数字在笔记里,和它出现在这里,是同一个理由。

  • 把检查做得更硬,是在为一个还不存在的用户做优化,而且没有天然的停止点 —— 一套检查系统永远还能更健壮一点。

    COST连续七个工作时段整个投进了元工作,而那件真能产出一个用户的事,一寸没动。这件事本来有写下来的阈值:元工作超过百分之十五就触发一次清理。它跑在大约一百,而没有任何东西在检查这个阈值。那条「禁止不受检的规则」的规则,自己没有检查。

这些出自一本工作笔记,记的人是实际在干活的那些 agent,规矩是:没有引发它的那次事故、没有推导、没有写清代价,这一条就不能进。那些笔记里的「我」通常不是我。我的部分是纪律、裁决,和重跑 —— 包括那些把我自己先前的结论跑成错的。项目本身没有公开,所以这一页上关于它的一切都是陈述,不是凭据。

◧这些你可以自己跑

什么都不用克隆,什么都不用信。下面三条,在你已经有的终端里就能跑:

  • curl -s https://hh0hh.com/rules.json | sha256sum 返回的摘要,就是上面 demo 里每一条判定旁边印着的那个。规则表是发出来的,不是描述出来的。
  • npm run release 规则摘要过期、分享卡片过期,或者输出里任何地方还留着未处理的占位符,它就拒绝构建。
  • node scripts/check-placeholders.mjs --release 上面那条里的最后一项,单独拎出来。我手工往 dist/ 里塞回一个违规,确认它退出 1 —— 一个只被证明过绿的检查不是检查。

同一个动作,三次 —— 每次配一件仪器:

它们不是同一个标准执行的,所以每条自己标出来:

  • ■已强制 机器不用人催就会跑。破坏它会让一次提交、一个 CI 任务或那次工具调用失败。
  • ◧可运行 一条真会失败的真判据 —— 但得有人去敲那条命令。
  • □仅声明 在遵守,但没被检查。我要是停了,不会有任何东西变红。

□这些你跑不了

DevLoop 是公开的,所以下面属于它的那些行可以拿代码对。Verdict 和 Terrarium 不公开,DevLoop 仓库指向的那个后继者也不公开 —— 对这些,按上面那一块里的规矩,我是在告诉你机制是什么,而你是在信我的话。

判定来自一个没法讲述的东西

一个关于「跑过了」的说法,得由一个在这件事上撒不了谎的东西来付账。其余的一切 —— 包括这句话本身 —— 都是陈述。

Verdict

规则引擎按契约是同步的。加 `async` 会让调用点在编译期就挂掉,pre-commit hook 拦下这次提交。 ■已强制

DevLoop

一条正则在模型读到消息之前就选好模式并写下一个令牌。没有它,消耗额度的命令一律拒绝。 ■已强制

Terrarium

基准真值不是把引擎跑两遍。是第二份用 numpy 写的独立实现,运算顺序逐个表达式对齐。 ◧可运行

这条规则出处的那篇文章,自己也得解决同一个问题:一篇反对相信机器自述的论证,材料几乎全部由机器自述组成。它里面每一条证据都标了级别 —— 机器事实,还是陈述。

守卫也被守

你信任的守卫和真能工作的守卫是两回事,而这个缝隙从里面看不见。所以每一个都被故意弄坏一次。

Verdict

`build` 放在 hook 里面,因为曾经有一份报告说它在那儿通过了 —— 而那次提交的 hook 里根本没有 build 这一步。 ■已强制

DevLoop

一道关卡会数有多少检查真的跑了并通过。零个已验证的检查等于关卡坏了 —— 那是第三种结果,不是通过。 ■已强制

Terrarium

十个测试文件各自声明必须触发多少条断言。一个悄悄死掉的测试,长得跟通过了一模一样。 ◧可运行

他被自己的规则抓到过:一次故意的破坏静默地没生效,于是什么都没坏,那片绿也就什么都不意味着。「红检查必须被亲眼看着变红」这条规则就是从那次来的 —— 而它仍然不够。一个启动失败的探针同样退出非零,所以「检查变红了」和「检查根本没跑」会以同一个数字到达。有一轮四个红检查,结果四个都是后者。

「我没查」永远不许渲染成「没问题」

没检查和检查干净,在你强行把它们掰开之前是同一个退出码。所以一个不说清自己跳过了什么的判定,本身就是一次假绿。

DevLoop

一份没有登记任何不可裁定条款的章程会拒绝加载。不是警告 —— 是配置错误,并在消息里给出理由。 ■已强制

Terrarium

不可裁定的条款是一张表,每一次判定都带一句「另有 N 条未覆盖」的尾巴。给它们编一个启发式规则是明令禁止的。 ◧可运行

This site

准确率那一行,只在模型、温度、prompt 版本、运行次数四项全都握有真实值时才渲染。缺一项,整行消失。 ■已强制

Verdict 有一份书面的对应物:一份列出它的自动化无法验证什么的清单 —— 监管语义、模型升级之后的 prompt 遵循度、手工提交进去的凭据。

干活的那个,不提供评判它的东西

「读了这道关卡」和「打算绕过这道关卡」逐字节看是一样的,所以在管用的地方,答案是让绕行本身失效,而不是去检测意图。在不管用的地方 —— 任何走守卫看不见的路径碰到文件系统的东西 —— 诚实的退路是检测,而说出这一点,比假装守卫是个密封盒子要便宜。

DevLoop

关卡从工作树之外一份带指纹的副本里跑。缓存无条件重建,验收在干净检出上跑 —— 工作目录会撒谎,提交不会。 ■已强制

Verdict

审查用的子 agent 在自己的 frontmatter 里声明为只读。它们能标出问题;跑不了那条能证明问题的命令。 ■已强制

Terrarium

测试树和答案键是锁住的。重写一条基线是一次判断,不是一次操作 —— 而且重写过的基线照样产出一个看起来完全正常的分数。 ◧可运行

每一个结论都带着它的适用范围一起发

一个不带范围的结果不是结果。它覆盖什么、明确不覆盖什么、什么证据能推翻它 —— 而一个离它的主张还有一次点击的限定语,不算限定语。

Terrarium

每条裁决四个字段:覆盖什么、不覆盖什么、依据、什么能推翻它。后两个才是干活的。 □仅声明

Verdict

同一组文档跑两次,两个结果。他收窄的是措辞,不是波及面:在裁决这一层可复现,端到端从不。 □仅声明

This site

账目里的一行可以陈述一个机制,但绝不放分数,因为一个分数需要它的标记、范围说明和局限一起挨着,而一行里三样都放不下。 □仅声明

我先给自己开单

更正照发,哪怕它把标题结果变得更难看;而一个不明的原因就写成不明,不给它编一个。

DevLoop

一个一行的去重 bug 让输出 token 差了 30 倍。这次更正把我自己的标题结果从赢变成了输。它照发了。 □仅声明

This site

这一页曾经在源码里印过一个规则 ID、一个哈希和一个 PASS。三样都是编的。现在它是一个你可以自己重算的摘要。 ■已强制

Terrarium

一次 20 倍的提速被归档为「否决」:更快,但不是同一个世界。错误的历史划掉,从不删除。 □仅声明

Verdict 保留着一节叫「明确没有做的部分」,列出那些界面存在、后端不存在的功能 —— 包括一个 demo 最容易糊弄过去的那一个。
