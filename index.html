How I build with AI

Deciding by rule instead of by model is not a preference, it is a bill. Something has to define the change before the model sees it, deny the commands it should not run, and judge the result without asking it. I ran that by hand for months; five documents and a set of hooks became DevLoop, which is published and readable. It is version one: some of it did not survive contact with a better foundation, and what did is being rebuilt on top of that.

  1. Five documents define the change before the model sees it

    Five source-of-truth documents and a 17-stage prompt pipeline define every change before the model sees it.

  2. A hook denies the command before it runs, not after

    Custom pre-execution hooks block dangerous commands and out-of-contract edits before they happen.

  3. The reviewer can flag a problem; it cannot run the command that would prove it

    Separate subagents audit diffs against spec. They can flag, but they cannot write.

  4. An exit code decides done, never the model’s own report

    Pre-commit runs type-check, tests and build; CI re-runs everything. Green is the only accepted evidence.

  5. Every incident pattern is mapped to the safeguard that now catches it

    10 documented incident patterns, each mapped to the safeguard that now catches it. One of them is the model reporting an exit code for a command that was not in the hook it named.

What I think the work is now

3 premises about working with models, 5 things that follow from them, and the parts they do not solve. Everything below is downstream of these — where a system disagrees with them, the system is what changed.

Plenty of good work goes into making these systems produce more, faster. This is the other half: the brakes and the instruments.

The premises

The premises, stated so you can disagree with them:

  1. A1A model forgets everything between runs.

    Nothing it learned last time survives except what someone wrote down and someone re-read. Every convention you rely on is re-established from scratch, or it is not there at all.

  2. A2The cost of producing work collapsed. The cost of checking it did not move.

    Generating a thousand lines and generating ten now cost roughly the same. Reading a thousand lines and reading ten do not.

  3. A3An error is asymmetric three ways: making one is free, finding one is expensive, and fixing one that has already been built on grows worse the longer it sits.

    The three costs are not merely different sizes. They point in different directions, so any process tuned for the cheap one is tuned against the expensive one.

What follows

What follows, and what each one forces:

  1. T1A constraint is exactly as strong as the judge is immune to the thing being judged. from A1

  2. T2Engineering value has moved from the producing side to the checking side. from A2

  3. T3Checkpoints have to be closer together than the rate at which errors get built on. from A3

  4. T4Intent can live in exactly three places: a person’s memory, which can be talked around; a file, which can be edited; and a program, which is neither. from A1

  5. T5A failure that changes no observable output accumulates until it is a disaster, and how often it happens does not come into it. from A3

What it does not solve

What it does not solve — measured, not anticipated. An earlier version of this list was written before the work started and read better; these are the ones that turned up afterwards:

  • A check can tell you a claim does not match the facts. It cannot tell you the reasoning behind the claim was wrong. The claim stays well-formed, the check has no opinion about it, and the mistake is somewhere the check cannot see.

    COSTOne bad estimate of a root cause sat behind a green board for twenty-six commits. What broke the deadlock was someone going and measuring it, which is not a thing a gate can be made to do. This is the limit, not a gap: the honest response is to say which conclusions rest on judgement and stop implying the machinery covers them.

Honest limitations

Synthetic-data demo above; the real system is in development for one client and is not a public product. Accuracy is measured on clean digital English PDFs from that client’s document mix. Not scans, not photos. Rules encode my reading of public regulations, verified by tests, not by a licensed broker. No production-traffic claims.

How this demo works

This demo replays pre-recorded outputs of the real pipeline run against synthetic shipping documents — same extraction schemas, same rule engine, same verdict logic. Nothing here calls a network: no LLM API, no tracking, no data leaving your browser. Document values are invented; rule IDs and thresholds are simplified for display. The full system is still being built for that client; this replay is the honest public slice of what works today.
