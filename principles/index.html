What I think the work is now

3 premises about working with models, 5 things that follow from them, and the parts they do not solve. Everything below is downstream of these — where a system disagrees with them, the system is what changed.

Plenty of good work goes into making these systems produce more, faster. This is the other half: the brakes and the instruments.

The premises

The premises, stated so you can disagree with them:

  1. A1A model forgets everything between runs.

    Nothing it learned last time survives except what someone wrote down and someone re-read. Every convention you rely on is re-established from scratch, or it is not there at all.

  2. A2The cost of producing work collapsed. The cost of checking it did not move.

    Generating a thousand lines and generating ten now cost roughly the same. Reading a thousand lines and reading ten do not.

  3. A3An error is asymmetric three ways: making one is free, finding one is expensive, and fixing one that has already been built on grows worse the longer it sits.

    The three costs are not merely different sizes. They point in different directions, so any process tuned for the cheap one is tuned against the expensive one.

What follows

What follows, and what each one forces:

  1. T1A constraint is exactly as strong as the judge is immune to the thing being judged. from A1

    A model grading its own work is not a weak check, it is not a check. So the verdict goes to a rule engine, a process exit code, or a second implementation. But an exit code only counts while the thing being judged cannot reach the switch that turns the check on: I once disabled a guard by adding a trailing comment to the line it was reading, and it went on reporting zero violations.

  2. T2Engineering value has moved from the producing side to the checking side. from A2

    The interesting work is no longer writing the thing. It is building the apparatus that decides whether the thing is done — and then breaking that apparatus on purpose to see it go red.

  3. T3Checkpoints have to be closer together than the rate at which errors get built on. from A3

    A gate at the end is a gate after the damage, so the cheapest checks move down to the tool call. That stops the writes the tool layer can see. It does not stop the others: two shell one-liners went straight through the same hook and the files were really written. Deciding whether a command will write a file is the halting problem wearing a hat, so that channel is checked by snapshotting before and after instead — which is catching it, not preventing it.

  4. T4Intent can live in exactly three places: a person’s memory, which can be talked around; a file, which can be edited; and a program, which is neither. from A1

    This is why writing a rule down keeps failing. A rule that matters gets a mechanical criterion — a command whose output is the rule — and the only way to make it stop complaining is to actually do the thing.

  5. T5A failure that changes no observable output accumulates until it is a disaster, and how often it happens does not come into it. from A3

    Silence is not a signal, so nothing throttles it. A cleanup routine captured its own output and never checked the return code; every failure was swallowed, and the count ran to 2,983 abandoned working directories before 86 GB of disk stopped it. Failures now have to be loud even when nobody is watching — especially then.

One held back

One more was derived and is being kept out:

T6Any mechanism that makes a fix more expensive the longer it waits will end up preserving the error rather than the fix. candidate — held, not adopted

It needs an amendment to be promoted, and the phase that would trigger it has not arrived. Three separate problems already look like instances of it, which is an argument for taking it seriously and not an argument for adopting it early.

What it does not solve

What it does not solve — measured, not anticipated. An earlier version of this list was written before the work started and read better; these are the ones that turned up afterwards:

  • A check can tell you a claim does not match the facts. It cannot tell you the reasoning behind the claim was wrong. The claim stays well-formed, the check has no opinion about it, and the mistake is somewhere the check cannot see.

    COSTOne bad estimate of a root cause sat behind a green board for twenty-six commits. What broke the deadlock was someone going and measuring it, which is not a thing a gate can be made to do. This is the limit, not a gap: the honest response is to say which conclusions rest on judgement and stop implying the machinery covers them.

  • The coverage of a check is not observable from its result. Where a check finds its subject by matching text, "matched nothing" and "there is nothing to match" arrive as the same answer — and it reports a pass either way.

    COSTEight checks audited one by one; six had the same defect, every one reproduced by hand rather than reasoned about. Changing two words in a comment made an over-budget document quietly compliant. It is worse than a silent failure, because a silent failure is silence and this is a green tick.

  • A check whose switch is reachable by the thing it checks. Adding a trailing comment to one line of a protected-paths list made the pattern match nothing at all — so a file could be edited and the guard watching that exact file reported zero violations. One edit did the trespass and hid it.

    COSTStill open. The fix needs two things at once — every pattern must be shown to match something that exists, and an intentionally empty one must say so out loud — and half a fix here is worse than none, because it restores confidence without restoring coverage.

  • Of the rules this framework writes down, most are enforced by nobody. Twenty-nine rules; five have a machine check. Eleven more could have one and do not. Twelve cannot have one at all — "was the root cause actually measured?" does not become an exit code.

    COSTPublishing the ratio is the cost. Leaving it out would let the thing read as a complete system of constraints, and it is a fifth of one. The number is in the notes for the same reason it is here.

  • Hardening the checks is optimising for a user who does not exist yet, and there is no natural stopping point — a checking system can always be made more robust.

    COSTSeven consecutive working sessions went entirely into meta-work and moved the one thing that would produce a user precisely nowhere. There was a written threshold for this: meta-work above fifteen per cent triggers a cleanup. It ran at roughly a hundred, and nothing was checking the threshold. The rule against unchecked rules had no check.

These come out of a working notebook kept by the agents doing the work, under a rule that an entry is not admissible without the incident that produced it, the derivation, and what it costs. The first person in those notes is usually theirs. Mine is the discipline, the rulings, and the re-runs — including the ones that made an earlier conclusion of mine wrong. The project itself is not public, so everything on this page about it is an account rather than a receipt.

◧YOU CAN RUN THIS

Clone nothing, trust nothing. Three of these work from a terminal you already have:

  • curl -s https://hh0hh.com/rules.json | sha256sum Returns the digest printed beside every finding in the demo above. The catalogue is served, not described.
  • npm run release Refuses to build on a stale rule digest, an out-of-date share card, or an unresolved placeholder anywhere in the output.
  • node scripts/check-placeholders.mjs --release The last of those, on its own. I put a violation back into dist/ by hand and confirmed it exits 1 — a check only ever proved green is not a check.

The same move, three times — one instrument each:

They are not all enforced to the same standard, so each says which:

  • ■ENFORCED A machine runs it unprompted. Breaking it fails a commit, a CI job, or the tool call.
  • ◧RUNNABLE A real criterion that really fails — but someone has to type the command.
  • □STATED Followed, but unchecked. If I stopped, nothing would go red.

□YOU CANNOT RUN THESE

nonconstant and DevLoop are published, so their rows below can be checked against the code. Verdict and Terrarium are not — for those, by the rule in the block above, I am telling you what the mechanism is and you are taking my word for it.

The verdict comes from something that cannot narrate

A claim about execution has to be paid for by something that cannot lie about execution. Everything else — this sentence included — is an account.

Verdict

The rule engine is synchronous by contract. Adding `async` fails the call sites at compile time, and the pre-commit hook stops the commit. ■ENFORCED

DevLoop

A regex picks the mode before the model reads the message, and writes a token. Without it, quota-spending commands are denied. ■ENFORCED

Terrarium

Ground truth is not the engine run twice. It is a second implementation in numpy, operation order matched expression by expression. ◧RUNNABLE

The essay this rule comes from had to solve its own version of the problem: an argument against trusting machine self-reports, assembled almost entirely from machine self-reports. Every line of evidence in it carries a tier — machine fact, or account.

The guard is guarded

A guard you trust and a guard that works are different things, and the gap is invisible from the inside. So each one gets broken on purpose, once.

Verdict

`build` sits inside the hook, because a report once said it passed there — in a commit whose hook had no build step. ■ENFORCED

DevLoop

A gate counts the checks that ran and passed. Zero verified checks is a broken gate — a third outcome, not a pass. ■ENFORCED

Terrarium

Ten test files each declare how many assertions must fire. A test that dies quietly looks exactly like one that passed. ◧RUNNABLE

He has been caught by his own rule: a deliberate break that silently failed to apply, so nothing was broken and the green meant nothing. The rule that a red check must be seen to go red dates from that — and it is still not enough. A probe that fails to start also exits non-zero, so “the check went red” and “the check never ran” arrive as the same number. One round of four red checks turned out to be four of those.

“I didn’t check” may never render as “it’s fine”

Not-checked and checked-clean are the same exit code until you force them apart. So a verdict that does not name what it skipped is itself a false green.

DevLoop

A constitution registering no unjudgeable clause refuses to load. Not a warning — a config error, with the reason in the message. ■ENFORCED

Terrarium

Unjudgeable clauses are a table, and every verdict carries an “N not covered” tail. Inventing a heuristic for them is banned. ◧RUNNABLE

This site

The accuracy line renders only when model, temperature, prompt version and run count all hold real values. Miss one and the row disappears. ■ENFORCED

Verdict carries the written counterpart: a list of what its automation cannot verify — regulatory semantics, prompt adherence after a model upgrade, credentials committed by hand.

Whoever does the work does not supply what judges it

Reading the gate and planning to route around it are indistinguishable byte for byte, so where it works the answer is to make the route-around ineffective rather than to detect intent. Where it does not work — anything that reaches the filesystem by a path the guard never sees — the honest fallback is detection, and saying so is cheaper than pretending the guard is a sealed box.

DevLoop

The gate runs from a fingerprinted copy outside the worktree. Caches rebuild unconditionally, and acceptance runs on a clean checkout — the working directory lies, the commit does not. ■ENFORCED

Verdict

Reviewer subagents are declared read-only in their own frontmatter. They can flag a problem; they cannot run the command that would prove it. ■ENFORCED

Terrarium

The test tree and the answer keys are locked. Rewriting a baseline is a judgement, not an operation — and a rewritten one still produces a score that looks perfectly normal. ◧RUNNABLE

Every conclusion ships with its range

A result without its scope is not a result. What it covers, what it explicitly does not, and what evidence would overturn it — and a qualifier one click away from its claim is not a qualifier.

Terrarium

Four fields per ruling: what it covers, what it does not, the basis, and what would overturn it. The last two are the ones that do the work. □STATED

Verdict

Two runs of one document set, two results. He narrowed the wording rather than the blast radius: reproducible at the ruling layer, never end to end. □STATED

This site

A ledger row may state a mechanism and never a score, because a score needs its badge, its scope note and its limitations beside it, and one line has room for none of them. □STATED

I write my own ticket first

Corrections ship even when they make the headline worse, and an unknown cause is written down as unknown rather than given one.

DevLoop

A one-line deduplication bug moved output tokens 30×. The correction turned my own headline result from a win into a loss. It shipped. □STATED

This site

This page once printed a rule ID, a hash and a PASS in its source. All three were invented. It is now a digest you can recompute. ■ENFORCED

Terrarium

A 20× speedup is on file as a rejection: faster, but not the same world. Wrong history is struck through, never deleted. □STATED
